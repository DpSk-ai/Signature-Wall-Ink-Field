# 原项目与墨场版本的差异

| 区域 | 原项目 | 墨场版本 |
|---|---|---|
| 页面组织 | React 页面、字体声明、网络与导出集中在 main.tsx | 保留三个入口，按签到、展墙、管理、状态、字体、笔迹和展场绘制拆分组件 |
| 手机签到 | 表单、外链字库和文本预览 | 作品首屏、真实字形标本、可重写校样、提交状态和带落点坐标的回执；局域网 HTTP 可生成请求 ID |
| 大屏 | 海报配色、独立二维码元素、旋转姓名 | 深度排序的墨带、计数与可扫码展签，共用 1920 × 1080 坐标；以人数控制艺术层浓度 |
| 布局 | 顺序扫描候选框，按人数尝试降字号，旋转边界未计入 | 按持久空位分散选址，三个开场大字幅、错列高度、长名双行、保留隐藏占位；旧记录按旋转后的外包框避让 |
| 动画 | CSS 逐字延时与定时状态切换 | 针对选中字形使用笔顺中线遮罩，字形准备就绪后才开始，最后一笔完成后确认状态。支持冻结与减少动态 |
| 实时状态 | HTTP 与 WebSocket 初始化可能互相覆盖 | WebSocket 快照作为初始与重连状态，按 ID 更新；显隐同步完整快照；连接计数随连接变化广播 |
| 存储及 API | Fastify、better-sqlite3、WAL、认证与既有 API | 保留这些接口和数据表，新增可选 expectedStatus 及 split_at 列。历史记录保留原值。支持指定数据目录及监听主机 |
| 字体 | 7 个实际声明的远程家族、无本地字体文件 | 24 个自托管真实字体，cmap 覆盖检查、按需分片、补字提示、服务端相同白名单 |
| 导出 | 4K 图另绘白底文字；CSV 使用前端已知记录 | 大屏与 4K 使用同一作品渲染器、字形和位置；PNG 与 CSV 均下载实际 Blob，CSV 按管理员最新记录导出 |
| 运行 | Vite 与 tsx CLI，旧 QA 留有绝对路径和历史结果 | Vite 与 Node 的 tsx 导入方式，生产仍由 Fastify 提供同源服务；测试服务和数据库独立 |
| 依赖 | 原 package-lock.json | lockfile 相同，生产依赖集合相同；视觉层用 Canvas 2D、React、CSS 与既有 qrcode |

## 数据恢复记录

原 ZIP 提供 signature-wall.db-wal 和 signature-wall.db-shm，未提供主数据库。核验 WAL 头、salt 和逐帧滚动校验和，共 82 帧、22 个提交点；最后一次已提交状态覆盖 10 个完整数据库页。新建主库来自这些页，SHA-256 为 `e4967262a6423de01ee4514f2b83b3527e735dab41d506ad007caf1ff9ee58c5`。只读 SQLite integrity_check 返回 ok，读回 5 条完整记录。交付包中的数据库未混入本轮测试数据。

## 文件清单与差异

`changed-files.tsv` 列出源 ZIP 与本包间逐文件 A / M / D 状态。文件按 Linux/Windows 均可识别的路径分隔符归一化。自引用的清单和 patch 以新增控制文件列出。`source.patch` 提供业务源码、配置、测试和 README 的统一文本差异；字体二进制、截图、SQLite 和生成的覆盖表可按文件清单及字体台账核对。原 ZIP 中历史截图、旧报告、缓存和写死机器路径的核验脚本已从运行包移出，原上传件保留。

ZIP 不包含已安装的 node_modules、平台专属原生二进制或重复的 dist。执行 README 中的 npm ci 和 npm run build 即可重建。截图见 tests/artifacts，真实字体与笔顺文件已经就位。
