## 导出一致性

将 4K PNG 用 Lanczos 缩至 1920 × 1080 后，与同一状态的大屏截图逐像素比较。三个颜色通道平均绝对差为 3.30, 3.05, 2.88（8-bit，范围 0–255）。两次绘制的采样率及文字抗锯齿不同。二维码保留可扫描的静区。交付的示例二维码编码临时测试地址；现场二维码使用现场大屏访问地址。

## 首轮失败及修复

- 开发环境限制 tsx CLI 的本地控制管道、网络接口枚举及桌面版 Chromium 的进程单例套接字。改为 Node 的 tsx 导入入口，测试服务监听回环地址。Playwright 默认浏览器下载地址返回 403，验收改用可运行的标准 Chromium Headless Shell。Windows 说明使用项目锁定依赖和常规 Playwright 安装流程。
- 一次后台重构把 React 钩子带入了刷新函数，登录与恢复隐藏记录用例报错。移除嵌套调用，重新执行全部 14 个端到端用例。
- 初次书写采样发现 writing 和 complete 使用了不同的 React key。保留永久 ID 作为 key，完成时不替换姓名节点，重新用像素与坐标采样验收。
- 在同时渲染报告的繁忙环境下，旧版每帧最多累计 90 ms，三人书写队列未能在原用例的 9 秒窗口内完成。改为累计实际时间，并仅为活动字幅增加兜底时钟；复跑原门槛，3/3 正常完成。
- 最初的长姓名测试样本实际有 13 个码点，API 正确返回 400。修正为 12 个码点，覆盖边界和两行显示。
- 补测 CSV 时临时下载路径返回 canceled。导出改为从管理员接口读取即时记录，两个导出共用延后释放 Blob URL 的下载函数；测试使用明确的保存路径并核对实际文件内容，最终通过。
